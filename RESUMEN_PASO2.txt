✅ lib/fechas-colombia.ts - MOTOR DE DÍAS HÁBILES COLOMBIANOS
   └─ Características:
      • Cálculo de Pascua (Meeus/Jones/Butcher algorithm)
      • 9 festivos fijos (Año Nuevo, Reyes, Día del Trabajo, etc.)
      • 7 festivos móviles (Semana Santa, Corpus, Sagrado Corazón, etc.)
      • Ley 51/1983: Traslados a lunes (Epifanía, San Pedro y San Pablo)
      • Cálculo de vencimientos descontando festivos
      • Semáforo automático (Verde/Ámbar/Rojo/Vencido)
      • Cache en Map para performance
      • Integración con tabla festivos_colombia
   
   Funciones principales:
   • sumarHabiles(fecha, dias) → Sumar días hábiles
   • habilesEntre(inicio, fin) → Contar días hábiles
   • habilesRestantes(vencimiento) → Días hábiles al vencimiento
   • calcularSemaforo(dias) → Estado semáforo
   • calcularPascua(año) → Fecha de Pascua
   • obtenerFestivos(año) → Lista festivos del año

✅ lib/supabase.ts - CLIENTE SUPABASE CON CRUD HELPERS
   └─ Características:
      • Cliente público (supabase) para operaciones desde cliente
      • Cliente admin (supabaseAdmin) para backend
      • 20+ funciones CRUD para todas las tablas
      • Helpers especializados (KPI, almacenamiento, búsqueda)
      • Error handling robusto con logging
      • Integración automática con cálculo de días hábiles
      • Auditoría en tabla auditoría
   
   CRUD disponibles para:
   • peticiones (crear, obtener, actualizar, listar, críticas)
   • correspondencia (entrada/salida)
   • contratos (crear, actualizar ejecución, supervisión)
   • proyectos y hitos (planificación)
   • eventos_agenda (calendario)
   • pendientes (tareas y delegaciones)
   • Productores y asociaciones (módulo misional)
   • Archivos (Supabase Storage)

✅ lib/validations.ts - VALIDACIÓN CON ZOD
   └─ 15 Esquemas Zod implementados:
      • schemaCrearPeticion → Validar nueva petición
      • schemaCambiarEstadoPeticion → Cambiar estado
      • schemaAsignarResponsable → Asignar funcionario
      • schemaCorrespondenciaEntrada → Correo recibido
      • schemaCorrespondenciaSalida → Correo enviado
      • schemaCrearContrato → Nuevo contrato
      • schemaActualizarEjecucionContrato → Progreso contrato
      • schemaCuentaCobro → Cuentas por cobrar
      • schemaCrearProyecto → Nuevo proyecto
      • schemaCrearHito → Hito de proyecto
      • schemaCrearEventoAgenda → Evento/reunión
      • schemaCrearPendiente → Nueva tarea
      • schemaRegistrarProductor → Productor agropecuario
      • schemaRegistrarAsociacion → Asociación rural
      • schemaRegistroUsuario, schemaLogin → Auth
   
   Patrones regex:
   • REGEX_CEDULA: Cédula Colombia (8-10 dígitos)
   • REGEX_NIT: NIT con dígito verificador
   • REGEX_EMAIL: Email internacional
   • REGEX_TELEFONO: Teléfono fijo Colombia (10 dígitos)
   • REGEX_SECOP: Formato SECOP II
   
   Helper: validarFormulario<T>(schema, datos)
   → Retorna { valido, datos?, errores? }

✅ lib/resend.ts - NOTIFICACIONES POR CORREO (RESEND + REACT EMAIL)
   └─ 4 Funciones de envío implementadas:
      1. enviarNotificacionAsignacion()
         • Email al responsable cuando se asigna petición
         • Incluye: radicado, asunto, días restantes, enlace directo
         • Diseño institucional con identidad visual

      2. enviarResumenDiario()
         • Cron Job diario (7:00 a.m. zona Colombia)
         • Resumen de: peticiones críticas, contratos próximos, pendientes
         • Destinatario: Secretario y responsables

      3. enviarCitacionReunion()
         • Citación a participantes de evento/reunión
         • Incluye: orden del día, ubicación, fecha/hora
         • Soporta múltiples destinatarios

      4. enviarAlertaVencimiento()
         • Alerta cuando entra en semáforo Ámbar/Rojo
         • Aplica para peticiones y contratos
         • Mensaje urgente de cumplimiento legal

   Templates React Email:
   • EmailAsignacionPeticion() → Template para asignación
   • EmailResumenDiario() → Template para resumen
   • Diseño responsivo con CSS inline
   • Colores institucionales (#1F4E5F, #2E7D4F, #B87708, #B3261E)
   
   Auditoría:

   • Captura resend_message_id para tracking
   • Almacena contexto (radicado, contrato, tipo alerta)
   • Registro de errores con descripción

🔗 INTEGRACIÓN ENTRE LIBRERÍAS
═══════════════════════════════════════════════════════════════════════════════

Flujo: Componentes React → Validación → CRUD Supabase → Cálculos → Emails

1. VALIDACIÓN (lib/validations.ts)
   └─ Esquema Zod valida datos del formulario
   └─ Retorna { valido, datos, errores }

2. OPERACIÓN CRUD (lib/supabase.ts)
   ├─ crearPeticion(datos) inserta en Supabase
   ├─ Internamente llama a calcularSemaforo() del motor de días
   └─ Registra en auditoría

3. CÁLCULO VENCIMIENTOS (lib/fechas-colombia.ts)
   ├─ Obtiene festivos de festivos_colombia (en caché)
   ├─ Suma días hábiles descontando fin de semana + festivos
   └─ Calcula semáforo (Verde > 5 días, Ámbar ≤ 5, Rojo ≤ 2, Vencido < 0)

4. NOTIFICACIÓN (lib/resend.ts)
   ├─ Obtiene datos de Supabase mediante lib/supabase.ts
   ├─ Renderiza template React Email
   ├─ Envía mediante API Resend
   └─ Registra en historial_emails

5. TIPADO (lib/types.ts)
   └─ Proporciona tipos para todas las operaciones

📝 NOTAS IMPORTANTES
═══════════════════════════════════════════════════════════════════════════════

1. VARIABLES DE ENTORNO
   • Copiar .env.example → .env.local
   • Llenar SUPABASE_URL, ANON_KEY, SERVICE_ROLE_KEY
   • RESEND_API_KEY es opcional (fallará gracefully en dev)
   • Nunca comitir .env.local al repositorio

2. SUPABASE
   • Ejecutar SQL scripts en orden: schema_01 → schema_02 → schema_03
   • Verificar que RLS está habilitado
   • Configurar roles y políticas según el equipo

3. RESEND
   • Crear cuenta en https://resend.com
   • Obtener API key y configurar en .env.local
   • En desarrollo, los emails se simularán (MOCK)
   • En producción, se enviarán emails reales

4. FESTIVOS COLOMBIA
   • Tabla festivos_colombia tiene 38 festivos (2024-2025)
   • Después de 2025, actualizar con calcularPascua() para años siguientes
   • Motor es flexible y soporta cualquier año

5. TESTING
   • Cada librería en Paso 2 tiene validación de tipos
   • Paso 3 incluirá tests unitarios
   • Paso 4+ incluirá tests de integración
